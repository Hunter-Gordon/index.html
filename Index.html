🤖 AI Rankings Sync

Pick a sport below. The AI will search the web team-by-team for every current-season team in that sport, check for games that have been played since the record was last updated, and update each team's record, conference record, and streak automatically — no per-team review, it just runs. In the background it also researches opponent quality, average point differential, recent form (last 5–10 games), last season's record, head-to-head results, and a scouting note (playing style, key players, tendencies) — all of which now feed into how teams are ranked (including the Matchup Predictor, which reads this same data) and into the Scouting Database. Every verified game found during a sync is also written straight into that team's public Schedule — results and final scores update automatically, you don't need to touch the Schedule modal for games the AI already confirmed. Nothing is invented — if the AI can't find a stat, it leaves it blank.

How rankings use this: Win% is still the primary sort (like a real standings page). Opponent quality, point differential, recent form, and last season's record all nudge the Rating column up or down as tiebreakers/context. Head-to-head results are checked first whenever two teams would otherwise tie exactly on record — a team that beat a rival ranks above them at the same record. A "📅 schedule updated" tag in the log below means that team's Schedule (visible on its public profile) was also updated by this run.

🤖 AI API Key (OpenAI)

Paste your OpenAI API key here to turn on the AI features that still use it — article drafts, school logo lookup, team research, the bulk AI rankings sync, and the public Scout / Ask-the-database tab. (The Matchup Predictor no longer uses this key — it's calculated locally from the database.) It's stored only in this browser's localStorage, the same way the Gist token below works — it's never written into the site's files, and it's only ever sent directly to OpenAI's API when you actually use an AI feature. This same key also powers every AI feature inside the UC Experience (Owner Panel → UC Experience) — the API endpoint is shared, but every UC AI call is built from UC's own data only, never the schools/teams above.

⚠ Same tradeoff as the Gist token: this key lives in this browser's localStorage, so anyone with access to this device/browser (or dev tools on this page once the site is public) could read it out. That's fine while CIN·POWER is private/testing-only. Before you make it public, move the AI calls behind a small server-side proxy that holds the key instead of the browser — ask me and I'll help you set that up when you're ready. Note this also means the public Scout tab (both the main site's and the UC Experience's) only gets real AI answers on a browser that has this key saved; other visitors automatically fall back to a plain keyword search of the same database.

⚙️ GitHub Gist Sync

Connect a GitHub Gist so your data persists across deployments.
Setup:
1. Go to github.com/settings/tokens → Generate new token (classic) → check gist scope → copy token.
2. Go to gist.github.com → create a NEW secret gist → filename: cinpower_data.json → content: {} → Create.
3. Copy the Gist ID from the URL and paste below.

⚠ The token is stored only in your browser's localStorage (never sent to any server other than GitHub). Each device/browser needs to re-enter the token. Data is stored in your Gist and loaded automatically on every visit — this includes the UC Experience data (S.uc), so it syncs right alongside the main site.
